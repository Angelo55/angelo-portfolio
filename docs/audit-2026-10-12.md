# Full-stack portfolio audit — 2026-10-12

## Scope

This audit covered the Next.js architecture, public and private routes, responsive header, theme controls, hero motion, project and certificate showcases, document dialogs, recruiter assistant, contact flow, analytics, Supabase boundaries, CI, production headers, accessibility, performance, and deployment readiness.

## Prioritized findings and remediation

| Priority | Finding | Resolution |
| --- | --- | --- |
| High | Dark-mode dialogs retained white surfaces while inheriting light text, making project, resume, and certificate content difficult to read. | Added shared dark-theme dialog, action, certificate-detail, project-copy, and icon overrides. |
| High | `X-Frame-Options: DENY` blocked the portfolio's own resume and certificate iframes. | Changed the policy to `SAMEORIGIN`, preserving external framing protection while allowing intended same-origin previews. Open/download actions remain available when a browser cannot render embedded PDFs. |
| High | Profile metadata, social/resume controls, and certificate cards used white surfaces with light dark-theme text. | Added consistent dark surfaces, borders, shadows, and readable foreground colors. |
| Medium | Analytics could throw an unhandled server error when Supabase was unreachable. | Added guarded persistence with an explicit HTTP 503/no-store response. |
| Medium | Analytics and theme initialization could throw when browser storage was blocked; the scheduled analytics callback was not cancelled on unmount. | Added safe storage access, a valid ephemeral visitor identifier, guarded session deduplication, and idle-callback cleanup. |
| Medium | The private analytics dashboard could display zero metrics after a query failure, and sign-in could remain in a loading state after a network exception. | Added owner-visible error states, generic authentication errors, missing-configuration handling, input bounds, autocomplete, and `finally` cleanup. |
| Medium | Contact and chatbot inputs did not retain an explicit high-visibility keyboard focus ring after component styles removed the browser outline. | Added visible focus rings and bounded the contact email field to 254 characters. |
| Low | Analytics used a public fallback hash salt if `ANALYTICS_HASH_SALT` was missing. | Removed the predictable fallback; analytics now degrades to non-persistent mode unless all server-only persistence variables are present. |
| Low | Chat and analytics rate-limit maps retained client keys indefinitely on warm instances. | Added expired-entry pruning and a 2,048-bucket cap while preserving per-client limits. |
| Low | The chatbot accepted oversized and unexpected cross-origin requests before input processing, and provider JSON parsing could throw. | Added a 4 KB request limit, same-origin/canonical-origin validation, no-store responses, and guarded provider JSON parsing. |
| Low | The production assistant displayed DeepSeek Markdown emphasis markers literally and collapsed bullet line breaks. | Normalized safe text-only emphasis markers at the server boundary and preserved response line breaks in the chat bubble without adding an HTML/Markdown rendering surface. |
| Low | Any decorative hero logo could become the observed LCP asset, while only the Python logo loaded eagerly. | Marked the small above-the-fold hero SVG set as eager to remove inconsistent LCP warnings. |

## Functional and responsive verification

- Desktop and 390 × 844 mobile renders load with the correct page identity and no framework error overlay.
- Mobile header keeps the brand, theme control, and menu trigger aligned; the menu focuses its first link and restores trigger focus after Escape.
- Theme switching updates the accessible control label and persists the selected mode.
- Recruiter assistant opens, closes, traps focus, dismisses from outside/Escape, resets with New chat, and opens the PESO and resume resource dialogs.
- Dark-mode project and resource overlays now use readable surfaces and text.
- Native and trimmed contact validation block invalid or empty-looking messages before opening an email draft.
- Public API checks return HTTP 403 for unexpected origins and HTTP 400 for malformed same-origin input, with `Cache-Control: no-store`.
- Resume and certificate responses now return `X-Frame-Options: SAMEORIGIN`; the in-app audit browser does not provide a native PDF renderer for localhost, so the embedded pixels could not be validated there. The visible open/download fallbacks remain available.
- Production smoke testing confirmed the public assistant reaches DeepSeek, returns a grounded answer, preserves scannable line breaks without raw Markdown markers, and records no browser-console errors.

## Remaining limitations and follow-up

- Contact continues to open the visitor's email application rather than submitting to a server.
- In-memory rate limiting is intentionally best-effort per function instance. Move it to a distributed platform control if traffic or abuse justifies the added dependency.
- A strict nonce-based Content Security Policy is not included in this maintenance pass because it requires coordinated Next.js rendering and third-party compatibility testing. Existing nosniff, same-origin framing, referrer, permissions, and HSTS headers remain enabled.
- GitHub Actions uses version tags rather than immutable commit SHAs. Pinning actions is a future supply-chain hardening option.
- Embedded PDF rendering still depends on browser capability; direct open/download actions are the supported fallback.
